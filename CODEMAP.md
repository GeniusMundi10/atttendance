# ELT Attendance code map

- `contracts/kiosk.md` defines the first online kiosk punch.
- `contracts/face-enrollment.md` defines employee self-service issuance, kiosk claim/consent/capture, recovery, account-wide registration, and HR reset.
- `apps/android` owns the kiosk client. `KioskActivity.kt` handles punch, setup, first-time self-service and supervised enrollment, recovery, local camera self-test and receipts; `EnrollmentPolicy.kt` validates six-digit strings; `EnrollmentRecovery.kt` stores only claim/session references; `Capture.kt` owns multi-frame liveness capture. `LocalDeviceSetup.kt` and `SetupPolicy.kt` own unmanaged setup storage and validation.
- `features/attendance` belongs to the attendance agent. It owns the authoritative PostgreSQL punch transaction.
- `features/access` belongs to the people agent. It owns employees, account linkage and reader/site authorization.
- `features/biometrics` owns device evidence, encrypted face templates, employee-wide registration, self-service enrollment lifecycle, durable limits, HR reset audit, and supervised provisioning; `features/access` publishes active site assignments and HR/MFA reset authorization.
- `features/schedule` owns shifts, effective-dated employee/site assignments, holiday calendars, schedule reads and its audit trail. `schedule.ts` publishes `scheduleDays`, `scheduleDay`, `isWorkingDay`, `readSchedule` and holiday/shift lookups for other features; `manage.ts` owns HR mutations.
- `features/leave` calls the schedule interface when checking work dates and registers the accepted date for its existing request constraints. Requests are `PAID` (uses the one monthly paid day) or `UNPAID` (no balance effect; `002_leave_type.sql`), always need a note, allow one non-rejected request per date, and return the latest decision reason so employees see rejections.
- `features/schedule` defaults employees with no assignment to the seeded General Shift (`STANDARD_SHIFT_ID`: 9:30–18:00, 510 minutes after `002_standard_day.sql`, Sunday off, its holiday calendar), so leave works without per-employee shift setup.
- `platform/api.ts` dispatches signed kiosk enrollment/status/cancel/complete calls, authenticated employee issuance/status and HR reset, alongside existing receipt routes. `kiosk.ts` composes the single punch transaction, `auth.ts` verifies the portal token, `http.ts` bounds input and `db.ts` owns the pool.
- `apps/web/app` is the employee app. `AppShell.tsx` owns the one Supabase session (password sign-in/sign-up, approval wait, admin authenticator), the shared outline `Icon` set, the top bar (menu with Admin and Sign out) and the five-tab bar (`next/link` client navigation, sliding pill). Pages: Home (`Home.tsx`: Today card with a device-time `AnalogClock` and, while checked in, the `DutyStreams.tsx` canvas animation; face-registration steps with the six-digit code; recent days), `history`, `leave`, `corrections`, `settings` and `admin` (attendance lookup by month/employee/day, new accounts, leave decisions, face approvals and resets). `history/DayRow.tsx` is the one attendance-day row (full, or `slim` for Admin) shared by Home, History and Admin; `leave/LeavePortal.tsx` exports `LeaveRequests`, reused by Admin. Home exports `clock`, `dayLabel` and `duration` formatters. The API route delegates to the platform. `DEPLOYMENT.md` says what runs where.
- Local dev: `scripts/dev-web.mjs` runs `next dev apps/web` with the root `.env.local` (gitignored; HR flow `DATABASE_URL`) and then `.env` loaded, since Next otherwise reads env files from `apps/web`; `scripts/dev-db.mjs` runs a persistent loopback embedded Postgres for `.env`'s local `DATABASE_URL`. `.claude/launch.json` holds `db` and `dev`. Phones reach the dev server over USB with `adb reverse tcp:3000 tcp:3000`; debug kiosk builds accept `http://localhost`.
- `scripts/migrate.ts` applies versioned feature SQL with checksums, enables RLS and revokes Data API grants on sensitive tables. `scripts/test-features.ts` runs feature suites on a disposable database.
- `features/biometrics/self-service.test.ts` covers synthetic enrollment codes, employee-bound issuance, same-kiosk claim recovery, signed completion, encrypted first-template-only storage, no attendance side effects and reset idempotency; `tests/kiosk.test.ts` exercises signed device flows, authorization and committed receipts using `tests/database.ts`.
- Follow `README.md` for configuration, acceptance and commands. Each agent's feature README covers its operator steps and checks.
- `features/biometrics/self-service.ts` also gates code issuance on HR approval (`approved_at`), refuses a face that matches another active employee's template (`findRegisteredFace`, kiosk greets them by first name), and stores employee re-registration requests that an HR reset resolves. `features/access` numbers every employee with a unique `employee_code` (ELT00001…) and an optional `whatsapp_number`.
- Kiosk feedback: `Capture.kt` `PoseSweep` stops an already-registered face at its first (straight) step by matching the kiosk roster (`AlreadyRegistered`, ≥ .50 like punches) and lets tilt steps complete when a tilted frame reads poorly (that frame is left out of the template). `KioskActivity.kt` shows punch receipts and notices in a solid banner (`showBanner`: green receipt, orange notice), greets duplicates with `greetAlreadyRegistered`, and turns `ATTENDANCE_ACTION_ORDER` into plain text ("you already checked in at 7:56 PM") using `lastRecordedAt`, which `features/attendance` now returns with that error.
- `platform/whatsapp.ts` (`npm run whatsapp`) drains `attendance_outbox` into WhatsApp Cloud API template messages. `apps/android` `PunchWindow.kt` auto-starts IN before noon and OUT from 4 pm IST for a recognised face. `apps/web/app/settings` holds Biometric issues. `apps/mobile` is the Capacitor Android shell that loads the deployed portal (`ELT_PORTAL_URL`, `npm run mobile:sync`).
